# 后续课件更新与维护

## 先识别变化，再修改正文

原始资料放在本地`PPT/`，保留旧版原件及日期，不用新文件直接覆盖唯一旧副本。来源编号S01—S08与知识点编号保持稳定；新文件先判断是旧版替换、续讲还是独立补充。文件属性时间只能作为线索，正文和封面才决定实际知识变化。

```sh
npm run check:sources
python3 scripts/extract_sources.py
```

第一个命令检测新增、删除和哈希变化。提取器发现已有来源变更时，要求显式给出`--accept-change "变更理由"`，先归档旧清单和提取内容；这只是维护者明确接受来源变化，不代表教材已经同步。原始PPTX不随Git公开，需另外保留旧原件。

用LibreOffice导出时必须包含隐藏页、正确加载中文字体。运行`scripts/render_sources.py`并核对PDF页数，再渲染每页。对文本异常、公式、扫描图、程序图和作业表格查看单页。视频/动画需回到PPT原件，静态PDF无法替代播放检查。

## 更新知识和来源映射

在`sources/Sxx-topics.json`记录真实页段、深度、审阅页面、疑义与去向。逐页覆盖索引由这些记录生成，每一页只能出现一次。用正文中的`kp`标记定位受影响知识点，在原锚点处修订；移动内容时保留跳转或旧锚点。

新知识先补入，再处理重复旧段；不得为了压缩篇幅删掉公式适用条件。新增教材推导、外部参考和作者练习明确标注。原课件疑义在修订记录中列出页码、修订原因和独立验证方法。

## 计算与图形同步

`lib/models.mjs`是确定性计算模型，交互、结果和部分科学曲线共用。改变模型时先核查单位、边界和独立已知结果，再重跑：

```sh
node --test tests/models.test.mjs
node scripts/compute.mjs
node scripts/build-figures.mjs
```

图前说明观察目标，图后交代规律与限制。不要让一个图同时承担公式表、操作面板和全部证明。静态图需保持明暗主题和窄屏可读，动态组件提供静态回退。

## 完整性基线

`sources/content-baseline.json`保存每个知识点的正文哈希、公式与显式锚点，并把逐页审阅表绑定到实际来源哈希。质量检查会阻止无记录的删除或改写；只重新提取、导出PDF而没有重新确认审阅基线，不能把旧页的审阅状态自动沿用到新课件。若确实需要修改，先在`reports/change-log.md`解释原因，再运行：

```sh
node scripts/update-baseline.mjs --reason "具体说明修改及复核依据"
npm run validate
```

基线不是数学正确性的证明，只是帮助发现遗忘与意外重写。不要通过删除测试、降低阈值或清空基线让检查变绿。

## 部署和恢复

每个完成阶段提交明确文件，保留无关改动。GitHub Actions从同一份Markdown构建并部署GitHub Pages；构建版本清单保存Git commit、来源摘要和知识点数量。部署后核对线上`version.json`与预期提交，并抽查正文、公式和资源。

进度在仓库`reports/progress.md`，疑义在逐页主题与修订记录。恢复时先读这两处、查看Git状态和最近提交，再继续未验收部分。自动化检查不等于真实学生学习实验，验收报告须区分两者。
